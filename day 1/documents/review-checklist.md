# Чек лист на 8 пунктов
№1 Теги путаются между собой - tag = [] создаётся пустым и всего один раз, изза чего он распространяется на каждую заявку, а не присваевается каждой заявке свой
№2 Утечка данных - return tickets возвращает прямой доступ к глобальному списку tickets и внешний код может вызвать .clear() или изменить данные внутри списка в обход валидации
№3 Ошибка адресации в close_ticket - при попытке закрытия тикета, вероятно закроет чужой тикет, как как сравнивается не next_id, а ticket_id в котором единственный индекс это 0
№4 Ошибка деления на ноль - при попытке closed_share() при пустом списке closed будет ровняться 0, а 0 нельзя делить, изза чего выдастся ошибка
№5 Копирование не правильной информации - та же ошибка что и в №1,return ticket.copy() вернёт tag - общий для всех, изза чего его изменение приведёт к глобальному изменению для всех тикетов
№6 Валидация входных параметров - сама проверка if title == "": raise ValueError("Пустой заголовок") хорошая, но она проверяет только title, изза чегоостальные данные могут без проблем проходить пустыми
№7 предсказуемость возвращаемых данных - в close_ticket() возвращется лобо True, либо False от чего результат не предсказуем, что может нечаяно удалить данные или предоставить не правильтый вывод о статусе информации
№8 Оформление кода - в create_ticket() создание класса сложно читаемое, предпочтительно писать каждый атрибут наследущейстроке, от чего страдает и вывод данных, которые сложно читать

# Замечания
№1 Нарушение поведения - функция list_tickets(user) полностью игнорирует переданного пользователя и возвращает прямую ссылку на весь глобальный список, что позволяет коду исказить данные
№2 Логическая ошибка адресации - в close_ticket идентификатор ticket_id используется как индекс массива, хотя генерация ID начинается с 1, и из-за смещения тикет с id=1 невозможно закрыть
№3 Падение программы - функция closed_share падает с критической ошибкой, если вызвать её до добавления первого тикета при делении на len(tickets), равный 0
№4 Разделяемое состояние в аргументах - Конструкция tags=[] приводит к тому, что теги одного тикета будут непроизвольно перетекать в другие тикеты, созданные позже
